# Winflow 时间线可视化计划

本文档描述 Winflow 的时间线展示方向。当前实现以本地 Web UI 为主，后续会逐步成熟化。

## 1. 目标

时间线不是精确计费工具，而是帮助用户快速回忆一天的工作节奏：

- 某个时间点大概在做什么；
- 某个应用/任务大约持续多久；
- 哪些时段频繁切屏；
- 哪些应用占据了主要时间。

## 2. 数据来源

默认只使用本地前台应用事件和活动带聚合结果：

- `/api/timeline`：原始前台事件；
- `/api/bands`：活动带；
- `/api/apps/usage`：应用级使用统计。

默认不使用截图、OCR、浏览器历史或 LLM 总结。

## 3. 当前 UI

当前本地 Web UI 包含：

- 控制台首页；
- 活动带视图；
- 原始事件视图；
- `/usage` 应用使用统计预览页；
- 图标映射和 exe 图标展示。

## 4. 视觉方向

推荐采用横向时间轴：

- 横轴表示时间；
- 条带表示活动区间；
- 轨道只用于避免重叠，不绑定应用；
- 应用品牌色或映射色用于区分；
- 默认简洁，hover 时展示使用时长、命中次数等细节。

## 5. 交互原则

- 默认不展示敏感标题；
- hover 展示统计，不展示浏览器标签页；
- 支持按日期查看；
- 后续支持缩放和平移；
- 短事件应降噪，避免整页嘈杂。

## 6. 近期迭代

- 将 HTML/CSS/JS 从 `app/web.py` 继续拆到 `static/` 或模板文件；
- 为活动带时间轴增加独立前端模块；
- 增加空状态、错误状态和采集器状态提示；
- 为 `/usage` 和 `/api/bands` 增加 schema 文档；
- 保持所有展示遵守隐私默认值。

## 7. 验收标准

- 时间位置正确；
- 重叠活动不会互相覆盖；
- 细碎事件不会淹没主要活动；
- 浏览器不会展示标签页或站点；
- 应用图标清晰；
- 页面无需外部服务即可运行。
